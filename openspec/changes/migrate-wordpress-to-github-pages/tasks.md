## Explicit Gates

- **Delivery gate — resolved for apply planning:** The forecast exceeds 400 changed lines. Owner selected `auto-chain` with `feature-branch-chain`; implementation must proceed in measured chained slices instead of one oversized diff.
- **Privacy gate — public artifacts sanitized:** Owner selected public-artifact sanitization. Excluded source records are referenced by source IDs only; raw WXR remains sensitive/untracked and must stay out of public source/output/CI.
- **Evidence gate — before promotion or cutover:** Resolve the approved public inventory, asset classification and footprint, reproducible Ruby toolchain, captured desktop/mobile references, and third-party asset/font/icon license evidence.
- **Publication gate:** GitHub Pages deployment, custom-domain/DNS changes, WordPress retirement, and backup deletion each require separate owner authorization. A route/resource failure, disclosure, or material visual/content damage stops rollout and invokes containment or rollback.

The proposed work units below are a planning split, not an approved PR chain. Keep each implementation work unit at or below approximately 350 changed lines (including tests and docs); measure additions plus deletions before review. Generated pages, manifests, lockfiles, and binary assets are not exempt. If one cohesive unit cannot meet the budget, pause for the pending delivery decision rather than compressing or omitting evidence.
